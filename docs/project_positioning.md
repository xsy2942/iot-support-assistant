# Project Positioning

这个项目要刻意和 `ai-recruit-agent` 拉开差异。

## 不走的方向

- 不主打招聘业务。
- 不主打候选人匹配、简历解析、面试评估。
- 不把亮点写成多 Agent 编排或长期记忆。
- 不把项目包装成通用办公 Agent。

## 当前项目定位

项目名称：

```text
IoT 设备技术支持知识库与工单助手
```

核心场景：

- 设备离线
- MQTT 连接超时
- 网关心跳丢失
- 固件升级失败
- 传感器采样异常
- 电压/温度/振动数据异常
- 安全风险与投诉类问题转人工

## 差异化能力

| 维度 | ai-recruit-agent | 当前 IoT 项目 |
|---|---|---|
| 业务领域 | 招聘、人岗匹配、面试 | IoT 售后、设备故障、工单 |
| 主要数据 | 简历、JD、候选人资料 | FAQ、错误码、产品手册、历史工单、遥测数据 |
| 核心判断 | 匹配度、候选人画像 | 故障分类、优先级、转人工路由 |
| 技术亮点 | Agent 编排、记忆、招聘流程 | RAG 知识库、遥测规则诊断、低置信度转人工、工单闭环 |
| 评测指标 | 匹配或推荐效果 | Top3 召回率、引用覆盖率、转人工准确率、诊断分类准确率 |

## 简历表达方向

建议强调：

```text
独立实现 IoT 设备售后知识库与诊断工单助手，围绕设备心跳、MQTT 连接、错误码、固件升级和传感器采样等场景，构建领域知识库、遥测诊断规则、低置信度转人工机制和工单闭环评测。
```

不要写成：

```text
实现一个多 Agent 智能客服系统。
```

这样会和招聘 Agent 在“Agent 应用”层面过于相似。
